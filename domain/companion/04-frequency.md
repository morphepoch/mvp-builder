# 04 消息触发与频次

交付类型：调度适配 + 频控纯函数 + 表达 Skill。

**心迹当前实现**：once / cron / interval 三类；30 秒扫描；每条约定维护一个下一跳；interval 在可用时间窗口内累计时间，按 days×[1−jitter,1+jitter] 采样。`days=0.5` 表示约半个窗口的间隔，不保证自然日恰好两条。投放按用户稳定打散，同小时不跨小时。深夜、重复、正聊着和该不该说主要由字条与主 agent 判断；用户预算、免打扰偏好与未回复退避在主动性 README 中仍属待办。

**本次实现**：`frequency.py` 是可在模型调用前执行的候选检查。它不启动时钟、不读库、不发消息，也不实现 once/cron/interval 调度。宿主可接现有调度器，或参考心迹的 `proactive/projection.py`、`spec_schema.py`、`timing.py`。

新增可调默认值：22:30–09:00 免打扰、软触达日 2/周 5、最小间隔 6 小时、正在聊天延后 30 分钟、连续未回复按 3/7/14/30 天退避。它们是本次起始方案，未验证最优值，也不是心迹当前运营配置。

检查顺序：用户启用 → 已发去重 → 硬提醒资格 → 到期/过期 → 已验证明确提醒 → 软触达授权 → 免打扰 → 正在聊天 → 日/周额度 → 间隔 → 未回复退避。返回 send/defer/silence 及 reason；defer 之后再次检查 expiry。

宿主必须给 now 使用用户本地时区，其他时间必须带时区。只有宿主依据已确认的具体时刻同时设置 `hard=true,user_requested=true`，才绕开软预算；不能让模型自己设置 hard。“有空找我聊”虽是用户偏好，也仍按软频控。

没有 soft_contact_opt_in 或具体授权时不发软触达；contact_enabled=false 和 already_delivered 优先于所有提醒。用户不回复不能被当作继续提高频次的理由。未回复 streak、日周计数都只统计成功送达的软主动触达，不把用户问一句答一句也算作主动骚扰。

并发保障：此纯函数不能单独保证限额。宿主须以 `(tenant,user,character,occurrence_id)` 唯一键防重复，并在事务内原子预占预算、读取最新开关和序列号。模型生成期间用户停用或主动发来消息，要在发送前再次检查。成功送达才提交预算；明确失败释放；未知结果保留待回执核对。

`deterministic_spread()` 只返回稳定偏移分钟数，不执行调度，也不保证不跨小时。需要复刻心迹时由宿主把偏移限制到 `59-due_at.minute`，避免把 23:50 变成次日。

被动聊天另外控制：同一会话串行合并未处理消息、新消息打断过时生成、一个业务回复可以拆多个气泡。日周软预算不应用于正常问答。当前可移植包没有提供入站 dispatcher、气泡发送节奏或并发调度服务。
