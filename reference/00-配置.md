## 一、技术与运行环境
- 产物形态：【单页 Web 应用 / 移动端 H5】← 替换
- 技术栈：**原生 HTML + CSS + JS 单文件**（沙箱零构建、零依赖、打开即跑，演示最稳）
- 禁止引入任何需要 `npm install` 才能跑的东西，除非我明确同意。
- 所有外部资源必须可离线降级：图片用 SVG/占位块，字体用系统字体栈兜底。
- 不许用 CDN 引外部 JS/CSS —— 断网就白屏，现场演示会死。

## 二、密钥与配置

把下面这段原样放在文件顶部作为配置区，代码里只读变量，不许在别处硬编码：

```js
const CONFIG = {
  // ── 主对话模型：DeepSeek（OpenAI 兼容格式）──
  LLM_BASE_URL:    "https://api.deepseek.com",
  LLM_ENDPOINT:    "https://api.deepseek.com/chat/completions",
  LLM_API_KEY:     "<用户提供的 DeepSeek api_key>",
  LLM_MODEL:       "deepseek-chat",
  LLM_TRACKING_ID: "<可选：Tracking ID>",

  // ── 记忆层：硅基记忆 seemem v2 ──
  MEM_BASE_URL:  "https://ms.seemem.com/api/v2/memory",
  MEM_TOKEN:     "<用户提供的 seemem 租户 token>",
  MEM_TENANT_ID: "<无需填写，token 自动解析>", // 仅备查，调用时不要传，token 会自动解析
};
```

调用方式：
- **DeepSeek**：`POST {LLM_ENDPOINT}`，头 `Authorization: Bearer {LLM_API_KEY}`，
  body 是标准 OpenAI Chat Completions 格式。
  ⚠️ **DeepSeek 没有图像生成能力**，产品里任何要出图的功能都得改成 SVG/占位/上传。
- **seemem**：`POST {MEM_BASE_URL}/save` 等，头 `Authorization: Bearer {MEM_TOKEN}`。
  ⚠️ **租户 ID 不要传**，服务端从 token 解析。详见 P5。

## 三、质量铁律
1. **功能闭环**：每个按钮、输入框、链接都必须有真实响应。禁止点了没反应、
   `alert('待开发')`、`console.log` 占位、跳空白页。做不了就别放这个控件。
2. **状态完整**：每个交互至少覆盖 空态 / 加载中 / 成功 / 失败 / 无网络 五种状态。
3. **数据可信**：mock 数据必须像真的（真实中文姓名、合理时间、有波动的数值），
   不要 `测试1 测试2`、不要 `Lorem ipsum`。
4. **响应式**：桌面与 375px 移动端都不能出现横向滚动条或元素重叠。
5. **不许偷偷缩水**：实现不了或时间不够，**必须明说哪条没做、为什么**，
   不许悄悄跳过后报「已完成」。
