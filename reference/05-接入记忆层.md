# P5 · 接入硅基记忆 seemem（记忆层）

给产品接上长期记忆。**本阶段不需要读技能**——下面的接口契约我已核对过官方
开发者文档，**按这个写，不要自己猜、也不要去搜**。

## 凭证（已在 P0 的 CONFIG 里）

```
MEM_BASE_URL = https://ms.seemem.com/api/v2/memory
MEM_TOKEN    = <用户提供的 seemem 租户 token>
租户ID       = <无需填写，token 自动解析>   ← 仅备查，调用时不要传
```

## 接口契约（已核实）

- **鉴权**：请求头 `Authorization: Bearer {MEM_TOKEN}`
  - ⚠️ **租户 ID 不需要传**，服务端从 token 自动解析注入。
  - ⚠️ v1 用裸 token、v2 必须加 `Bearer`，**两套不通用，不要混调**。我们用 v2。
- **Content-Type**：所有 POST 必须 `application/json`，其他类型会被拒。
- **user_id**：每个接口都要显式传。**POST 放请求体，GET/DELETE 放 query 参数。**

### 核心三接口

| 用途 | 方法与路径 |
|---|---|
| 写入一轮对话 | `POST /save` |
| 召回相关记忆 | `POST /recall` |
| 生成总结（日报/周报/月报） | `POST /summary` |

### 其他可用接口
`POST /summary/list`、`GET /summary/{id}`、`DELETE /summary/{id}`、
`GET /person/options`、`POST /media/search`、`POST /topic-event/search`、
`POST /corrections`、`GET /corrections/{id}`、`POST /corrections/{id}/retry`

### 请求示例

写入（每条消息带 `idempotency_key` 防重复）：
```json
POST https://ms.seemem.com/api/v2/memory/save
{
  "user_id": "u_10086",
  "session_id": "s_20260908_01",
  "occurred_at": "2026-09-08T09:00:00",
  "messages": [
    {"role": "user", "content": "……", "idempotency_key": "s_20260908_01-1"},
    {"role": "assistant", "content": "……", "idempotency_key": "s_20260908_01-2"}
  ]
}
```

召回（纯读，不写会话、不触发抽取）：
```json
POST https://ms.seemem.com/api/v2/memory/recall
{ "user_id": "u_10086", "query": "上周聊的那个方案后来定了吗" }
```

召回返回的是**序列化好、可直接进 prompt 的一段文本**。标准用法：
```js
messages = [
  { role: "system", content: `以下是关于该用户的记忆：\n${recalled}` },
  { role: "user",   content: userInput },
]
```
然后把这个 `messages` 发给 DeepSeek（P0 的 `LLM_ENDPOINT`）。

## ⚠️ 四个必须处理的坑（不处理演示一定翻车）

1. **业务错误的 HTTP 状态码大多仍是 200。**
   成败必须以**响应体里的 `code` 字段**判断，绝不能只看 HTTP status。
   请封装统一请求函数强制检查 `code`，全项目只走这个函数。

2. **记忆不是写完就能查。** `/recall` 在写入后**数秒到数分钟**才生效。
   → 界面上不要让用户写完立刻期待召回命中；
   → **演示前必须预热**：提前把演示要用的对话写进去，别现场写现场召回。

3. **超时要放宽**：`/summary` 是同步 LLM 调用，客户端超时 **≥ 60 秒**；
   `/save` 且 `async_exec=false` 时 **≥ 90 秒**。默认几秒超时会直接失败。

4. **降级必须做**：记忆服务不可用时，产品要能退化成「无记忆的普通对话」
   继续可用，并给用户一个轻提示，**不许整个应用白屏或卡死**。

## 你要做的

1. 写一个 `memory.js`（或对应模块），封装 save / recall / summary，
   内含统一 `code` 检查、超时配置、失败重试、失败时的降级返回值。
2. 接进主对话流程：**每轮对话结束后异步 save；每次用户提问前先 recall 再拼 prompt。**
   save 不要阻塞界面。
3. 按 `PRD.md` 定的「记忆应用点」，把召回结果真正用起来 ——
   不能只塞进 prompt 就完事，要在界面上让用户**看得见记忆在起作用**
   （例如显示「我记得你上次提到……」这类可感知的回应）。
4. 做一个开发者自测入口（隐藏页面或控制台命令），能手动触发
   save / recall / summary 并看到原始返回，方便现场排查。
