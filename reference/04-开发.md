# P4 · 开发：按子 PRD 逐个实现

`DESIGN.md` 已确认。**继续沿用 P3 已读的 `frontend-design` 技能来写代码**，
本阶段不需要读新技能。严格遵守 P0 的铁律。

## 开发顺序
按 `prd/README.md` 定的顺序，**一次只做一个子模块**。
每做完一个，给我变更摘要 + 自检结果，我说「继续」才做下一个。
不要一口气全写完再给我看 —— 那样出问题无法定位。

## 每个模块的实现要求

1. **对着子 PRD 的交互元素表**，把表里每一行都实现掉，一行都不许漏。
2. **全部使用 `DESIGN.md` 的 CSS 变量**，不许硬编码颜色和阴影值。
   如果发现设计规范缺了某个场景需要的样式，**先告诉我，我们补进 DESIGN.md**，
   不许自己临时编个值写死在代码里。
3. **每个交互都要有反馈**：点击有按压态，请求中有 loading，
   成功有确认，失败有可读错误信息和重试入口。
4. **数据流要真**：状态集中管理，界面从状态渲染，
   不许直接操作 DOM 打补丁造成状态与界面不一致。
5. **DeepSeek 调用**用 P0 的 `CONFIG`，走 `POST {LLM_ENDPOINT}`，
   标准 OpenAI Chat Completions 格式，流式输出优先（体验好很多）。

## 做完一个模块，先自己验一遍再交给我

对照子 PRD 的交互元素表**逐行**回答：

| 元素 | 已实现? | 点了会怎样 | 异常分支做了吗 |
|---|---|---|---|

任何一行答不上来或答「暂未实现」，就不算做完，回去补。
**不许把没做完的东西报成做完了。**
